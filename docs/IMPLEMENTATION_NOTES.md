# Implementation notes

This file is for QA. It records every place where the implementation makes a choice the spec
leaves open, deviates from the spec, or only partly meets a requirement. Each entry starts with
the REQ id. Requirements not listed here are implemented as written. Test names follow §7 of
`REQUIREMENTS.md`.

## Tooling and repository

- **§6 / test command.** On Node 22, `node --test test/` does not accept a directory
  (`Cannot find module …/test`), so `npm test` runs `node --test test/*.test.js`. All test names
  from §7 exist with exactly those names. A few extra tests were added, such as
  `parsers agree with three.js loaders`, `file size limit` and `no remote URLs`.
- **REQ-090.** Playwright **WebKit could not be downloaded in this environment** (the proxy
  download failed). The smoke test `test/smoke/smoke.spec.mjs` defaults to WebKit at 390×844.
  It was run and passes with the installed Google Chrome: `S2P_BROWSER=chrome npx playwright test`.
  QA should run it with WebKit where it can be installed.
  - "Camera position changed" is checked by comparing canvas screenshots before and after the
    drag, which needs no test hook in the app.
  - Failed requests are counted from the offline reload onwards. Before that, the scripted
    reloads abort in-flight requests (`net::ERR_ABORTED`), which is navigation noise rather than
    a network failure.
  - The first import shows the one-time "iOS may delete app data…" notice, because headless
    browsers deny `persist()`. The test dismisses it.
- **REQ-072.**
  - `three@0.187.0` from npm has **no `build/three.module.min.js`**. It ships only
    `three.module.js`, which imports `three.core.js`. Both are vendored unminified (about 2.1 MB,
    precached). The import map maps `three` to `./vendor/three/three.module.js`.
  - `GLTFLoader`, `OBJLoader`, `PLYLoader` and `BufferGeometryUtils` are vendored as listed,
    plus `SkeletonUtils`, which `GLTFLoader` imports. The app does **not** load them at runtime.
    The spec (§4 conventions, REQ-074) requires a pure core with no three.js that runs in the
    worker and in Node, so parsing uses in-repo parsers in `src/core/`. The vendored loaders
    serve as reference oracles in tests (`parsers agree with three.js loaders`,
    `three.js GLTFLoader reads the export`).
  - Only `devDependencies` are used: `three` (pinned to exactly 0.187.0 so Node tests resolve
    the bare `three` import), `fake-indexeddb`, `@xmldom/xmldom` and `@playwright/test`.
- **REQ-071 / REQ-074.** `src/precache-list.js` is generated by `tools/gen-precache.mjs` and is a
  classic script (`self.S2P_PRECACHE = […]`), because `sw.js` loads it with `importScripts`.
  Module service workers are not reliable on iOS 17. It is the only file in `src/` that is not
  an ES module. Run `npm run precache` after adding files. The `precache complete` test fails if
  you forget.
- **REQ-070 / REQ-013.** The only `http://` string in app code is the SVG XML namespace
  `http://www.w3.org/2000/svg`, an identifier rather than a request. It is in `svg.js` and
  `drawing-view.js`. `test/structure.test.js › no remote URLs` allows exactly this string.

## Import (4.1)

- **REQ-001.** The glTF/GLB reader is in-repo (`src/core/parse-gltf.js`). See REQ-072 above.
  - It supports triangles, strips and fans; points-mode primitives become a point cloud; lines
    are ignored.
  - It reads `byteStride`, normalized attributes and data-URI buffers (self-contained `.gltf`).
  - The **first** base-colour texture is kept for display. If a file has several textured
    materials, only that one texture is shown, and UVs of other primitives are meaningless
    (wrong texture on them).
  - Sparse accessors are not supported (read as zeros).
  - `extensionsRequired` containing Draco or meshopt gives E-IMP-04. Other required extensions
    are ignored.
- **REQ-002.** Also reads optional per-vertex colours (`v x y z r g b`).
- **REQ-003.** Also reads `binary_big_endian`.
- **REQ-004.** Progress:
  - Parsing runs in the worker.
  - Fractional progress is reported only while parsing **OBJ**. GLB and PLY parsing is one
    synchronous step and reports stages (reading, preparing 3D view, done).
  - The overlay redraws at least every 250 ms with the stage and elapsed seconds, so the user
    always sees activity. The bar itself does not move during a long GLB parse.
  - Cancel calls `worker.terminate()` immediately.
  - E-IMP-05 is also used for more than 10 M points and for allocation failures (`RangeError`).
    The exact message text mentions triangles.
- **REQ-005.** **Deviation:** the heuristic uses the **longest bounding-box side**, not the
  diagonal. The spec's own acceptance case contradicts the diagonal rule: box(400,300,250) has a
  diagonal of 559 > 500, which would suggest ×0.001, but the test expects ×0.01. With the
  longest side, all three acceptance cases pass. The unit prompt is shown before
  auto-orientation, so orientation runs on correctly scaled data.
- **REQ-006** (COULD) is implemented. **REQ-007** (USDZ, COULD) is **not implemented**.

## Projects and storage (4.2)

- **REQ-010.**
  - Two object stores: `projects` (metadata, transform, annotations, settings, thumbnail) and
    `sources` (original file Blob). Listing projects never loads scan files.
  - Auto-save is debounced at 800 ms.
  - The project also stores `orientation` and `calibration` separately;
    `transform = scale(calibration) · orientation` is stored too, as the spec requires.
  - The thumbnail is taken from the 3D view after import: 256×256 JPEG, with quality stepped
    down until it is ≤ 30 KB.
- **REQ-011.** The `persist()` result and the "warning shown once" flag are two tiny
  `localStorage` flags. They hold no scan data (REQ-076).
- **REQ-012.**
  - Restoring a backup uses the backup GLB as the new project's source, with an identity
    transform. The calibration info is kept for the title block, but the scale is already baked
    in, so *Reset scale* on a restored project cannot undo the old calibration.
  - **Gap:** textures are not written into the backup or GLB exports. Vertex colours are. See
    REQ-055.

## 3D viewer and orientation (4.3, 4.4)

- **REQ-015.**
  - OrbitControls mapping: one finger orbits; two fingers pan and pinch to zoom (`DOLLY_PAN`);
    double-tap focuses the tapped point.
  - The major grid is 1 m. The 0.1 m minor grid is shown when the camera is less than 5 m from
    its target.
  - The axis gizmo is in the bottom-left corner. The pixel ratio is `min(dpr, 2)`.
- **REQ-016.** Each cluster's vertex is the mean position. Colour and UV come from the cluster's
  first vertex, so UV seams can show small texture artefacts in the display copy only.
- **REQ-017.** The "live section plane" is the red outline of the most recently computed plan
  cut, drawn at its height. It updates when the Plan tab recomputes.
- **REQ-018** (COULD) is **not implemented**.
- **REQ-020.** Clarifications that were needed for the acceptance fixtures, which are closed
  boxes with outward normals: their floor faces point down, so no candidate has
  "upward-facing" area.
  - Up-axis choice uses upward-facing area first. If every candidate has zero, it falls back to
    faces facing either way (|n·a| > 0.97).
  - Candidates within 5 % of the best count as tied. Ties resolve in the order +Y, +Z, +X, −Y,
    −Z, −X. This also stops a ceiling-heavy interior scan from flipping a +Y model.
  - Floor-like faces for the tilt fit and the floor level use |n·up| > 0.97, for the same reason.
  - `› facade no floor` feeds the plane as glTF (+Y given). For an OBJ, a single zero-thickness
    vertical plane is genuinely ambiguous: its normal axis would score as "up".
  - *Tap floor to level* uses the area-weighted mean normal and centroid of the selected patch
    (faces within 0.3 m whose normal is within 15°). For a planar patch this equals the
    least-squares plane.
  - *Up = …* buttons rotate and then re-run levelling and yaw alignment.
- **REQ-021.** The yaw correction uses the smallest rotation (±45°). The detected angle is
  reported mod 90°.

## Plan, sections, elevations (4.5)

- **REQ-022.** Chaining adds one step to the spec's pipeline: open chains whose end points meet
  within 3 mm are joined, and closed if both ends meet. Welding near-coincident points can
  create junction nodes that split a ring. The `› noise` fixture needed this. The 1 M triangle
  slice takes about 0.5–0.9 s in Node.
- **REQ-022b.** Marching-squares contours lie on cell borders. Each wall therefore gives an
  outer and an inner loop, about 0.5 cm (half a cell) on either side of the wall. Both loops are
  drawn. The test uses the outer loop (14.04 m against the 14.0 ± 0.05 m tolerance).
- **REQ-023.** **Precedence decision:** REQ-028 (MUST) fixes cut lines at 0.5 mm, and the
  REQ-051 test checks every cut line for that width. A single room (no wall pairs) would then
  fail if single-sided walls were drawn at 0.35 mm. So all cut lines stay 0.5 mm. Paired walls
  additionally get grey poche and a thickness label (`d=24`); single-sided walls get no label.
- **REQ-024.**
  - Openings are always detected from slices at 0.30 m and 1.00 m, whatever the plan cut height.
    Detection is skipped for models lower than 1.05 m.
  - Doors are drawn as a gap with the label `D w=90cm`; windows as a gap with a double line and
    `W w=120cm`. Both get a width dimension.
- **REQ-025.** The coverage outline and the depth-edge lines are both drawn as thin edge lines
  over the shaded image.
- **REQ-026.**
  - The section uses the **infinite** vertical plane through the cut line, not just the tapped
    segment. This matches the acceptance test: the cut line (2,−1)→(2,4) only overlaps the box
    for 1 m, yet a 3.00 × 2.50 m outline is expected.
  - The viewing side is chosen in a dialog ("Left side / Right side" of A→B) after the second
    tap, instead of tapping a direction arrow.
- **REQ-027.** Implemented in Views (*Level* tool). The marker snaps to view outlines.

## Dimensions, measuring, calibration (4.6)

- **REQ-029.**
  - Overall dimension: 16 mm from the bounding box. Chain: 8 mm. Per-segment dimensions sit
    5 mm inside the room (interior side of each closed ring).
  - A chain is only drawn if it adds points beyond the overall dimension.
  - DIN 406 ticks are 2 mm, 45°, drawn 0.35 mm.
- **REQ-030.**
  - **Spec arithmetic error:** for (0,0,0)–(3, 0.583, 1) the distance is
    √(9 + 0.3399 + 1) = 3.2156 m, so the text is **"321.6 cm"**, not "317.0 cm". The components
    are "Δh 316.2 cm, Δv 58.3 cm". `test/measure.test.js › distance format` asserts the correct
    values and the format.
  - Saved measurements: Plan (shown in plan drawings and exports) and 3D (shown in 3D).
  - **Partial:** measurements in Views are shown but cannot be saved.
  - The < 300 ms raycast on 500k triangles was not measured (three.js brute-force raycast); it
    is on the device checklist.
- **REQ-031.** The stored factor is cumulative (a second calibration multiplies). The title-block
  text uses the cumulative factor and the last reference length.
- **REQ-032.**
  - Scale bars by scale: 1:20 → 0–0.2–0.5–1 m; 1:25 → 0–0.25–0.5–1 m; 1:50 → 0–0.5–1–2 m;
    1:100 → 0–1–2–5 m; 1:200 → 0–2–5–10 m; 1:500 → 0–5–10–20 m; 1:1000 → 0–10–20–50 m. All are
    40–100 mm on paper (tested).
  - The north arrow (COULD) is **not implemented**.

## Markup (4.7)

- **REQ-040.**
  - Demolition on a segment: thickness comes from a detected wall pair; otherwise the user
    enters it (default 24 cm).
  - The fill side is towards the paired face. Without a pair, it is outward for room rings; the
    user can flip it.
  - Default height = highest scanned vertex within 0.2 m (plan distance) of the segment
    midpoint, i.e. the local floor-to-ceiling height.
  - Trim handles move along the original segment and snap to 1 cm.
  - For polygon markup, "length" = longest edge, area = footprint and volume =
    footprint × height (if a height is set).
  - Plan labels use the short German words *Abbruch* / *Neu*; the legend uses
    "Existing (Bestand)", "Demolition (Abbruch)" and "New (Neubau)".
- **REQ-042.** The CSV starts with a UTF-8 BOM, so Excel detects the encoding. Lines end in CRLF.
- **REQ-063.** One undo stack (100 steps) covers markup, sections, level markers, excavations,
  orientation changes and calibration. View settings (cut height, toggles) are not undoable.

## Terrain (4.8)

- **REQ-046.**
  - The reported area is the polygon's exact (shoelace) area. Volumes use cell sums as
    specified.
  - Polygon cells outside the height-map extent count as missing data. Their number is
    estimated as polygon area ÷ cell area − cells found.
  - The sloped target plane (c, COULD) is **not implemented**.
- **REQ-047.** Implemented. When a section crosses an excavation polygon, it draws the terrain
  profile, the target line (dashed) and hatched cut area in #8B5A2B. The height map is computed
  on demand.
- **REQ-048** (slopes, COULD) is **not implemented**. The excavation dialog shows the DIN 4124 /
  "estimate, not a site safety plan" note.

## Exports (4.9)

- **REQ-050.**
  - Every export uses the two-step flow: generate the file, then show "Ready — tap Share". The
    spec requires this only for files that take over 1 s; using it always keeps
    `navigator.share` inside a fresh user activation.
  - In an installed iOS web app (`navigator.standalone`), step 2 (`<a download>`) is skipped
    because of WebKit bug 275288, and the object URL opens in a new window instead.
- **REQ-052.**
  - *Fit* adds a 22 mm margin per side for dimension chains (14 mm without dimensions).
  - The "does not fit" message names the selected paper ("…A4 at 1:500" on A4); on A3 it is
    exactly the spec text. Choosing *Use 1:1000* is offered.
  - Headings use Helvetica-Bold. Text widths for centring come from the Helvetica AFM metrics.
- **REQ-053.** On A4 portrait the title block is 180 mm, the full drawing-area width.
- **REQ-054.**
  - Text is transliterated to ASCII (ä→ae, ± → `%%p`).
  - Dimension ticks are not exported; dimensions are extension lines, a dimension line and TEXT.
  - Text heights and dimension offsets assume 1:50.
  - LF line endings throughout.
- **REQ-055.**
  - Exported via three.js `GLTFExporter`. A Node `FileReader` shim exists only in tests.
  - If the scan has more than 2 M triangles, the display copy is exported, with a notice.
  - **Gap:** texture images are not exported (vertex colours are).
- **REQ-056** (COULD) is implemented as the *PNG* button in 3D. It renders at a pixel ratio of 2.

## PWA and usability (4.10, 5)

- **REQ-060.** The install hint shows on the Projects screen whenever the app is not running
  standalone.
- **REQ-062.**
  - Checked at 390×844 by the smoke test: no horizontal scroll, and every visible button has a
    name and is at least 44×44.
  - Long toolbars scroll horizontally inside themselves; the page does not.
  - Text colours were chosen for ≥ 4.5:1 contrast but were not machine-verified.
  - Heavy geometry runs in the worker. JPEG/PNG encoding of view images and GLB export
    (`GLTFExporter`) run on the main thread.
- **REQ-064.** The new worker waits. The banner's *Reload* sends `SKIP_WAITING`, and the page
  reloads only after that tap.
- **REQ-075.** Node checks in `test/perf.test.js` and `slice.test.js › performance` cover: plan
  slice of 1 M triangles < 1.5 s, elevation of 1 M triangles < 3 s, terrain volume over
  100 m² < 1 s, PDF+SVG+DXF < 2 s, and orientation of 1 M triangles < 5 s. The device rows
  (cold start, import times, fps, memory) are on the owner checklist (§9) and were not measured.

## Known limitations

- Merging several scans and multi-storey projects are out of scope (§1.2).
- No automated test exercises the UI beyond the smoke flow. These parts were exercised
  manually in headless Chrome during development:
  - demolition and section tools,
  - Views,
  - a terrain excavation with backup and restore,
  - dark mode.
- Not exercised on a real iPhone. Safari-specific behaviour still needs the §9 checklist:
  - Web Share with files,
  - storage persistence,
  - texture `createImageBitmap(…, {imageOrientation: 'flipY'})`.
